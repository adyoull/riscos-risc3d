# RISC3D 0.10

RISC3D lets RISC OS programs that draw with Mesa (OpenGL, OpenGL ES) use
the machine's GPU. Programs don't change: riscos-mesa's EGL and OSMesa use
RISC3D where a GPU driver is registered, and draw in software where none is.

## What's in it

- **RISC3D-0.04-6.zip:** `!RISC3D`, for `!Boot.Resources`. It is the same
  on every system, and is also the PackMan package RISC3D.
  - The RISC3D module 0.04.
  - Its GPU drivers, in `GPU`. Each starts only on the machine it is for:
    - **Linux3D 0.04:** RISC OS on Linux, with riscos-risc3d installed;
    - **V3DRender 0.13:** Raspberry Pi 4, 400 and CM4, on native RISC OS.
  - !RISC3D's !Boot loads RISC3D at start-up, and RISC3D loads the first
    driver in `GPU` that starts. Programs need nothing in their `!Run`.
    `*RISC3D` says which driver is in use.
- **riscos-risc3d_0.22-1_arm64.deb:** RISC OS on Linux's side.
  - rol-3d 0.19.
  - Debian's Mesa from trixie-backports (26.1.6). The Pi's GPU needs it for
    fixed-function lighting with textures.
  - !RISC3D itself comes from PackMan (riscos-harddisc installs it).
- **RISC3D-client-0.9.tgz:** the client library that riscos-mesa builds in.
  It is unchanged since 0.9.
