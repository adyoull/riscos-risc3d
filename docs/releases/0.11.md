# RISC3D 0.11

RISC3D's SWIs and errors move to the numbers RISC OS Allocations has
allocated:
- **RISC3D:** SWI chunk &5AF80, errors &823D00.
- **Linux3D:** errors &823C00.
- **V3DRender:** SWI chunk &5AFC0, errors &823E00.

This is a clean break: RISC3D 0.05 answers only the new numbers.

**Programs need riscos-mesa 20.3.5-22's !MesaLibs** (RISC3D client 0.11). Older
!MesaLibs don't find RISC3D, and their programs draw in software.

## What's in it

- **RISC3D-0.05-1.zip:** `!RISC3D`, for `!Boot.Resources`. It is also the
  PackMan package RISC3D.
  - The RISC3D module 0.05.
  - In `GPU`:
    - **Linux3D 0.05:** RISC OS on Linux;
    - **V3DRender 0.16:** Raspberry Pi 4, 400 and CM4, on native RISC OS.
  - `GPU.Licences` and `GPU.GPL-2` for V3DRender.
- **RISC3D-client-0.11.tgz:** the client library riscos-mesa builds in. Only
  the SWI numbers changed.
- **riscos-risc3d 0.22-1** (RISC OS on Linux's side, rol-3d 0.19) is
  unchanged, and comes through ROL's Updates.

A program that must have RISC3D can check with
`RMEnsure RISC3D 0.05 Error This program needs !RISC3D`.
